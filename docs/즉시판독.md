# 스코어카드를 올리는 즉시 판독시키기

한 번만 해 두면 되는 설정이다. 다 하면 사진을 올린 지 **1~2분**이면 표에 타수가 채워진다.

## 왜 필요한가

GitHub의 예약 실행(cron)은 적어 둔 주기를 지키지 않는다. `read-scorecard.yml`에
5분마다로 적어 두었지만 실제로 측정한 결과는 이랬다.

| | |
|---|---|
| 설정값 | 5분 |
| 실제 중앙값 | **59분** |
| 실제 평균 | 73분 |
| 가장 긴 간격 | **210분** |
| 실행률 | 396회 중 **28회 (7%)** |

무료 공개 저장소의 예약 작업은 "이 시각 **이후 언젠가**"라는 뜻이고, GitHub이 붐비면
통째로 건너뛴다. **주기를 더 줄여도 소용없다.** 그래서 기다리는 대신 깨우기로 했다.

```
사진 업로드
   └ payload.scoreRequests에 '대기'로 저장
        └ 앱이 kickScorecardWorkflow() 호출        (api.js)
             └ Supabase 함수 kick-scorecard
                  └ 대기 요청이 있는지 확인
                       └ GitHub workflow_dispatch API
                            └ 판독 → stats.js 커밋 → Pages 배포 → 표에 반영
```

**토큰은 앱에 두지 않는다.** 이 저장소는 공개라 클라이언트 JS에 넣으면 그대로 새어 나간다.
토큰은 Supabase 쪽에만 있고, 앱은 함수를 부르기만 한다.

---

## 1. GitHub 토큰 만들기

<https://github.com/settings/personal-access-tokens/new>

| 칸 | 값 |
|---|---|
| **Token name** | `jtfag-kick` (아무거나) |
| **Expiration** | 원하는 기간 (만료되면 판독이 다시 느려지니 길게) |
| **Repository access** | **Only select repositories** → `JTFAG` 하나만 |

**Permissions → Repository permissions** 에서 딱 하나만 켠다.

```
Actions ............. Read and write     ← 이것만
그 밖의 모든 항목 ..... No access
```

> `Contents`는 주지 말 것. Actions 권한만 있으면 워크플로를 돌릴 수 있고,
> 그 이상은 이 용도에 필요 없다. 토큰이 새어도 남이 코드를 고치지는 못한다.

**Generate token** 을 누르면 `github_pat_...` 로 시작하는 값이 한 번만 보인다. 복사해 둔다.

---

## 2. Supabase에 토큰 넣기

Supabase 대시보드 → 프로젝트 → **Edge Functions → Secrets**
(또는 **Project Settings → Edge Functions → Secrets**)

**Add new secret** 으로 하나 추가한다.

| Name | Value |
|---|---|
| `GH_DISPATCH_TOKEN` | 1번에서 복사한 `github_pat_...` |

저장소가 옮겨 가거나 기본 가지 이름이 바뀌면 `GH_REPO`(기본 `seongho1203-star/JTFAG`),
`GH_BRANCH`(기본 `main`)도 같은 방법으로 넣을 수 있다. 지금은 안 넣어도 된다.

> `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 Supabase가 알아서 넣어 준다. 손대지 말 것.

---

## 3. 함수 올리기

대시보드에서 하는 게 제일 쉽다.

Supabase 대시보드 → **Edge Functions** → **Deploy a new function**

| 칸 | 값 |
|---|---|
| **Name** | `kick-scorecard` ← **이름이 정확해야 한다** |

편집기에 `supabase/functions/kick-scorecard/index.ts` 의 내용을 통째로 붙여 넣고 **Deploy**.

CLI를 쓴다면 이 한 줄이다.

```bash
supabase functions deploy kick-scorecard
```

---

## 4. 확인

앱에서 `📋 스코어 등록`으로 사진을 하나 올려 본다.

- **`🚀 판독을 시작했습니다`** 토스트가 뜨면 성공이다
- <https://github.com/seongho1203-star/JTFAG/actions> 에 바로 실행이 뜬다
- 1~2분 뒤 새로고침하면 표에 타수가 있다

토스트가 안 뜨면 브라우저 콘솔에 이유가 찍힌다 (`판독 깨우기 실패:` / `건너뜀:`).

| 콘솔 메시지 | 뜻 |
|---|---|
| `GH_DISPATCH_TOKEN이 설정되지 않았습니다` | 2번을 안 했다 |
| `GitHub이 거절했습니다: 403` | 토큰 권한이 모자라다 (Actions = Read and write 인지 확인) |
| `GitHub이 거절했습니다: 404` | 저장소 이름이나 토큰의 저장소 선택이 틀렸다 |
| `대기 중인 요청이 없습니다` | 저장이 아직 안 닿았다. 드문 일이고, 예약 실행이 곧 처리한다 |
| `조금 전에 이미 깨웠습니다` | 20초 안에 두 번 눌렀다. 정상이다 |

---

## 안 해도 앱은 돌아간다

이 설정을 안 하면 예전처럼 예약 실행을 기다릴 뿐이다(중앙값 한 시간). 등록 자체는
정상으로 되고, 깨우기가 실패해도 앱은 오류창을 띄우지 않는다 — 급하면 Actions 탭에서
직접 돌리면 된다.
