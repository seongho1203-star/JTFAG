# 리그 데이터 백업 켜는 법 · 되살리는 법

앱 전체 상태(`jtfag_league`의 한 줄)와 정산 금액(`jtfag_money`)을 **하루 한 번 자동으로** 날짜별로 남깁니다.
누가 잘못 저장하거나 낡은 폰이 덮어써도 이 백업으로 되돌릴 수 있습니다.

## 켜기 (한 번만)

1. Supabase 화면 → `SQL Editor` → `supabase/backup.sql`의 내용을 **통째로 붙여넣고 Run**.
   (`jtfag_backups` 표가 만들어집니다. 여러 번 실행해도 안전합니다.)
2. GitHub 저장소 → `Actions` → `리그 데이터 백업` → `Run workflow`(종류 `manual`)로 한 번 돌려 본다.
   초록이면 끝입니다. 이후 매일 한국 시각 새벽 4시 17분쯤 저절로 돕니다.
   (필요한 비밀값 `SUPABASE_URL`·`SUPABASE_SERVICE_KEY`는 이미 다른 워크플로가 쓰고 있어 따로 넣을 것이 없습니다.)

> 이 표에는 정책이 없어 **앱(anon 키)은 읽지도 쓰지도 못합니다.** 정산 금액이 들어 있어서 일부러 그렇게 했습니다.
> 백업 내용을 보려면 Supabase `Table Editor`에서 보세요.

## 어떻게 남기나

- 어제와 **내용이 같으면 새로 안 남깁니다.** (저장 도장 `_rev`는 내용이 아니라서 뺍니다.)
- 비었거나 망가진 데이터는 **백업하지 않고 워크플로를 빨갛게 실패**시킵니다 — 나쁜 백업이 좋은 백업을 밀어내지 않게.
  실패하면 GitHub이 메일로 알려 줍니다.
- 직전 백업의 절반 아래로 데이터가 줄었으면 노란 경고가 뜹니다(백업은 남기고, 직전 것도 그대로 있습니다).
- 보관: 30일이 지난 것은 지우되 **일요일(한국 시각) 것은 180일**까지 남깁니다. `직접`·`복구 직전` 백업도 180일. 최근 5개는 늘 남깁니다.

## 되살리기

`Actions` → `백업 되살리기` → `Run workflow`. **세 번에 나눠서** 합니다.

1. `backup_id`를 **비운 채** 실행 → 로그에 최근 백업 목록(번호 · 한국 시각 · 종류 · 크기)이 나옵니다.
2. 번호(또는 `latest`)를 넣고 **`dry_run`을 켠 채** 실행 → 백업 시점과 지금 상태를 나란히 보여 주고 아무것도 안 고칩니다.
3. 확인했으면 `dry_run`을 **끄고** 실행 → 되살아납니다. 앱을 새로고침하면 보입니다.

- 고치기 **직전의 지금 상태는 자동으로 `pre-restore` 백업**됩니다. 잘못 되살렸다면 그 번호로 다시 되살리면 됩니다.
- 기본은 `payload`(일정·사진·미션·여행·공금 등)만 되살립니다. **정산 금액까지** 되돌리려면 `include_money`를 켜세요.
  금액은 백업에 있는 칸을 덮어쓰기만 하고, 백업에 없는 칸은 지우지 않습니다.
- 스코어(`stats.js`)는 저장소 파일이라 깃 기록으로 되돌립니다. 이 백업에는 안 들어 있습니다.

## 시험

`node tests/backup.js` — 가짜 DB로 백업·중복 건너뛰기·정리·망가진 데이터 거절·복구(dry run · 직전 백업 · 금액)를 확인합니다.
